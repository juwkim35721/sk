# 4-matrix

## 역할
과제 문서, 부속 스키마 문서, 데이터 분석 결과를 바탕으로 요구사항과 하드 제약사항을 분류하여 `sk/work/MATRIX.md`에 작성하고, **거시적 서비스 이용 맥락(이용 주체, 사용 빈도, 동시 수정 여부, 핵심 창출 가치, 범위 경계)부터 미시적 데이터 기준(데이터 간 차이점, 예외 처리, 허용 임계값)으로 이어지는 제안형 DM**을 통해 요구·제약 사항을 확정한다.

## 입출력 파일
- 읽기:
  - `sk/work/INBOX.md`
  - `README.md` 및 본문에 링크된 부속 문서
  - `sk/work/EDA_REPORT.md`
  - `sk/work/EDA_SUPPLEMENT.md`
  - `sk/work/MANAGERS.md`
  - `sk/work/MATRIX.md`
  - `sk/work/DM_LOG.md`
  - `references/MATRIX_TEMPLATE.md`
- 쓰기:
  - `sk/work/MATRIX.md`
  - `sk/work/OUTBOX.md`
  - `sk/work/DM_LOG.md`

## 번들 리소스
- 레퍼런스: `references/MATRIX_TEMPLATE.md`

## 작업 절차
1. `sk/work/INBOX.md`를 읽어 사용자의 특별 요구사항, 우선순위 지시, 또는 현업 담당자 DM 답장을 확인한다.
2. 초기 호출 시 `README.md`, 부속 문서(`data/README.md`, 출력 스키마 명세서 등), `EDA_*.md`를 읽고 `references/MATRIX_TEMPLATE.md`의 8대 항목(`ER-#` ~ `UG-#`)을 채워 `sk/work/MATRIX.md`를 작성한다.
3. 초기 호출 시 `sk/work/OUTBOX.md`에 아래 두 파트를 구분하여 작성한다.
   - **[Part A. 사용자에게 묻는 요구·제약 해석 및 기본안 확인 질문]**
   - **[Part B. 현업 담당자에게 보낼 거시->미시 제안형 DM 초안]**: 반드시 아래 **거시(넓은 맥락) -> 미시(구체적 데이터·임계값) 순서**로 번호를 매겨 작성한다.
     - **1) 거시 질문 (이용 주체 · 사용 빈도 · 창출 가치 · 운영 경계)**: 현업에서 이 업무로 가장 곤란했던 점과 우리 서비스가 창출해야 할 최우선 가치, 이 화면/결과물을 **누가·언제·얼마나 자주 쓰는지(데이터 변경 주기 및 다수 운영자 동시 수정 유무 포함)**, 타인에게 노출되면 안 되는 정보 경계
     - **2) 미시 질문 (데이터 근거 예외 처리 · 수치 임계값)**: **`[데이터에서 발견한 구체적 수치·차이점] + [현업 운영상 허용 임계값(최대 시간/거리/중복제한 등) 또는 예외 처리 기준 질문] + [별도 기준 없을 시 적용할 제안 기준]`**
4. 반복 호출(동일 세션 내 재호출) 시에는 변경되지 않은 기존 입력 파일들을 중복해서 다시 읽지 않고, 새로 갱신된 `sk/work/INBOX.md`만 읽어 사용자 의견과 담당자 답장(미기재 항목은 추천 기본안 채택)을 반영해 `sk/work/MATRIX.md`를 `[CONFIRMED]` 상태로 갱신하고 `sk/work/DM_LOG.md`와 `sk/work/OUTBOX.md`에 확정 내역을 적는다.
5. 담당자 답장에서 새로운 운영 조건이나 추가 제약이 확인되면 즉시 `MATRIX.md`의 `EC-#`(명시적 하드 제약) 또는 `ER-#`(명시적 요구사항)로 승격시키고, 추가 확인이 필요하면 `OUTBOX.md`에 후속 DM을 작성한다.

## 응답 지침
처음부터 데이터 숫자만 묻지 않고, 서비스를 누가·어떻게·얼마나 자주 쓰며 어떤 가치를 중시하는지(거시 맥락)부터 물어본 뒤 구체적 데이터 수치와 임계값(미시 기준)을 묻는 자연스러운 질문 흐름을 유지한다.

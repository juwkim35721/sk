# 기술 협업 · 엣지케이스 원인 분석(RCA) · 3대 독립 검증 문서 템플릿 (`references/TECH_VERIFICATION_TEMPLATE.md`)
> **생성 스킬**: `13-doc`
> **주의**: 작업공간 루트에 제공된 협업·검증 질문지 문서의 **원본 질문 문항과 헤더를 절대 훼손하지 말고 그대로 유지**한 채, 각 질문 아래에 프로젝트의 실제 코드(`app/*.py`, `tests/test_slice_*.py`)와 수치 근거를 들어 아래 3대 핵심 내용을 구체적으로 작성한다.

## 문항 1 대응 가이드: 데이터 정합성 · 엣지케이스 · 장애 원인 분석(RCA) 및 방어 구조
- **데이터 분석에서 발견한 숨은 제약 및 예외 처리 (`EDA_REPORT.md` / `MATRIX.md` 근거)**:
  - 실제 데이터에서 발견한 테이블 간 불일치, 비활성 후보 항목, 구간별 비대칭, 시계열 특이일 수치와 이를 방어하기 위해 `app/core_engine.py` 및 `app/data_loader.py`에 적용한 조건식 명시
- **오류 데이터셋 원자적 롤백 및 이전 결과 노출 차단 (`app/data_loader.py`, `app/db.py`)**:
  - `validate_dataset()`에서 필수 열·외래키(FK)·형식 오류 검출 시 구체적 실패 사유를 반환하고 DB 트랜잭션을 롤백해 기존 확정 결과를 보호한 구조, 그리고 새 데이터 적용 후 재계산 전까지 `is_stale` 플래그로 이전 결과 노출을 차단한 메커니즘 기술
- **실행 불가 조건 명시적 경고 (`unassigned_warnings`) 및 구현 중 해결한 RCA 사례**:
  - 극단적 파라미터에서 제약 미충족 대상을 조용히 빼지 않고 `unassigned_warnings`로 반환한 구조와, 슬라이스 검증(`SLICE_*.md`)에서 발견해 수정한 실제 버그(`BUG-N#`)의 근본 원인과 해결 코드 명시

## 문항 2 대응 가이드: AI 생성 코드 교차 검증 원칙 (3대 독립 검증 및 아키텍처·보안 감사)
- **구현 에이전트의 자체 테스트에만 의존하지 않은 2-세션 분리 및 3대 독립 검증 (`tests/test_slice_*.py`)**:
  1. **소규모 기준 케이스 정답 대조 검증 (Micro-Case Ground-Truth Verification)**: 정답이 확정된 2~3건의 최소 입력 케이스에 대해 실제 함수 반환값과 기대값을 대조한 테스트 함수명과 결과
  2. **하드 불변 조건 전수 검사 (Invariant Audit)**: 모든 필수 대상 누락 0건, 비대상 오배정 0건, 용량·시간·예산 상한 위반 0건을 검증한 불변 조건식(`assert`)
  3. **오류 주입 및 변이 검증 (Fault Injection & Mutation Testing)**: 잘못된 입력 주입 시 롤백 작동 확인, 그리고 핵심 제약 검사 코드를 임시로 우회했을 때 테스트가 정확히 실패(`FAIL`)를 감지하는지 확인한 테스트 유효성 검증 사례
- **클린 아키텍처(`SRP`) 및 권한·개인정보 화이트리스트(`to_user_dto`) 보안 감사**:
  - `verify_slice.py`를 통해 확인한 도메인 엔진 순수성(웹/DB 의존성 0건), 운영자 서버 권한 검증(`require_admin_role()`), 일반 구성원 조회 응답에서 타인 민감 정보를 제거한 `to_user_dto()` 검증 내역

## 문항 3 대응 가이드: 엔지니어의 설계 통제 · AI 제안 선별 거절(`REJECTED`) · 점진적 고도화
- **판단과 계산의 분리 및 결정론적 통제 (`app/core_engine.py`)**:
  - 요구사항 해석과 아키텍처 설계는 현업 담당자 DM 합의(`DM_LOG.md`)로 확정하고, 모든 수치 계산과 제약 판정은 난수 없는 결정론적 코드(`core_engine.py`)로 고정하여 동일 입력 대비 100% 재현성을 확보한 원칙
- **과잉 기능 및 비결정론적 AI 제안 선별 거절 (`Cut List` & `FEEL-N# REJECTED`)**:
  - 초기 제안된 비결정론적 메타휴리스틱 탐색이나 요구 범위를 벗어난 과잉 기능(예: 담당자가 불필요하다고 확인한 동시성 잠금 또는 외부 API 연동 등)을 구체적 엔지니어링 근거로 거절(`REJECTED`)하고 핵심 정합성에 집중한 사례
- **상향식(Bottom-Up) 슬라이스 구현 및 점진적 고도화 이력**:
  - 최하위 모듈(`config -> db -> data_loader -> core_engine`)부터 스터브 없이 완성한 뒤 상위 API·UI를 조립하고, `BUILD_PROGRESS.md`와 `PLAN.md`(`Addendum`)를 통해 점진적으로 완성도를 높인 협업 과정
